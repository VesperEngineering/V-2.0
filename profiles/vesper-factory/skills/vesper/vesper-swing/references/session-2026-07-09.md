## Key Issues Found

1. **VWAP cross was a firehose.** 2,612 signals with avg score 9.2 means the filter was useless. Root cause: any penny-cross of VWAP with 1.5x volume got score 7+. Fixed with 3-gate tightening (0.15% cross threshold, 0.10% separation, 2x volume). Also added bearish cross-below-VWAP.

2. **Gap reclaim never fired.** `prev_close` dict initialized empty and never populated. Fixed with lazy Massive REST API seeding on first ticker encounter.

3. **3,057 signals is still too many** even after LLM filtering. Need position management layer (max 3 open, daily loss cap, EOD flat) before this is usable for paper trading.

4. **Venv contamination by Hermes PYTHONPATH.** The global PYTHONPATH env var (pointing to Hermes site-packages) shadows the swing-scope venv packages. Rebuilding the venv with `PYTHONPATH=""` prefix fixed it.

## PowerShell Venv Contamination

On Windows, the global PYTHONPATH env var (set by Hermes) causes swing-scope venv imports to fail. The batch file approach (`cmd /c "D:\swing-scope\start.bat"`) works because cmd clears PYTHONPATH. For bash terminal sessions, the Hermes shell doesn't have this variable so it works fine.

**Full fix:** When rebuilding the venv from PowerShell, always prefix pip commands with `PYTHONPATH=""` to prevent packages landing in the wrong directory.

## WebSocket Debugging Path

The following issues were encountered and fixed:
1. `_running = False` in `__init__` prevented `while` loop from executing — program exited silently after "Connecting..."
2. `additional_headers` kwarg on `websockets.connect()` unsupported on Windows — removed
3. Massive auth/subscribe responses are arrays `[{...}]` not dicts — added `isinstance(auth_data, list)` guard
4. VWAP field in AM events is `'a'`, not `'vw'` — corrected bar parsing
5. Subscription format: `"AM.AAPL,AM.MSFT"` not `"AM.AAPL,MSFT"` — per-ticker prefix required
