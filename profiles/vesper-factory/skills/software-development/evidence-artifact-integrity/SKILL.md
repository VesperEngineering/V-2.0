# Evidence Artifact Integrity

## Use when

Use for local report, audit, model-evaluation, shadow-execution, or other evidence code that turns structured inputs into persisted receipts. It applies even when the lane has no external execution authority.

## Procedure

1. **Make the receipt self-verifying.** Preserve complete frozen inputs in the receipt. Before persistence, rebuild the expected receipt from those inputs and reject anything whose canonical serialization differs. Do not trust a `PASS` flag, a caller-provided digest, or partial metadata.
2. **Validate the evidence contract.** Enforce source freshness, admitted-universe consistency, exact factor/input keys, finite numbers, deterministic ranking, and explicit authority fields. A no-execution receipt must directly state each relevant execution flag as false.
3. **Constrain persistence.** Accept only an existing absolute artifact root chosen by the trusted caller. Derive the final dated name internally. Reject relative paths, traversal, symlink/reparse-point roots, and arbitrary caller-selected output filenames. Do not create unchecked parent trees.
4. **Bound hostile source reads before parsing.** For any receipt loaded from a writable or untrusted local path, use `open("rb").read(MAX_BYTES + 1)` and reject oversized bytes before JSON parsing or hashing. Do not rely on `stat()` plus `read_bytes()`: a check/read race can still cause an unbounded allocation. Test this by simulating a false-small stat and asserting the unbounded-read path is never called.
5. **Make persisted-status validation total.** Validate exact scalar types before set membership or ordering comparisons (`type(state) is str`; `type(schema_version) is int`; `type(lease_count) is int`). This rejects JSON booleans and prevents list/object values from raising `TypeError`. Apply the same strict predicate to readers and writer-side newer-status suppression so a valid receipt can safely replace malformed persisted status.
6. **Publish artifact sets atomically.** When a receipt has companion files such as checksums, write all contents in a private staging generation directory, fsync them, then atomically publish the directory. If a completed dated generation already exists, return it only when every file verifies; otherwise fail closed rather than overwrite it.

   **Windows reparse/TOCTOU boundary.** For a local store that claims Windows-safe containment, path checks (`resolve`, `exists`, attribute probes, `os.replace`, or reopen-by-path) are insufficient. Pin the root directory with a native handle, create and reopen direct children through `NtCreateFile` using `OBJECT_ATTRIBUTES.RootDirectory` and `OBJ_DONT_REPARSE`, and validate exact bytes from opened handles. Reject ancestor-component reparse traversal by opening and retaining every lexical ancestor with `OPEN_REPARSE_POINT` and no delete sharing, validating its type/tag/final path; final-root equality alone is weaker and leaves mount-point uncertainty. Bound handle-based enumeration by total child count and cumulative name bytes, then re-enumerate/admit immediately before success and require exact membership drift closure. Validate constructor-time invariants on every public receipt/recovery posture object so callers cannot mint finalized, anchored, append-only, immutable, or non-local claims directly. Prefer a target-host-proven no-replace rename relative to that same root handle. If rename FFI remains unproven, a narrower direct-final `FILE_CREATE` protocol may be admitted only after an executable target-host probe proves collision preservation, bounded reopen/read, handle enumeration, and crash-truncated residue causing all-or-nothing `RECOVERY_BLOCKED`; state explicitly that it has no atomic visibility or automatic repair. Recovery must remain handle-bound in either design. Reject mapped/remote drives (`GetDriveTypeW == DRIVE_REMOTE`), bound handle-reported leaf size before allocating a buffer, and semantically replay the exact staged bytes before publish so a digest-valid but unreplayable poison leaf cannot become durable. See `references/windows-native-handle-containment.md` for the full post-GREEN adversarial gates.
7. **Anchor append-only ledgers.** A JSONL hash chain alone cannot detect valid suffix deletion. Each entry digest must commit to the complete chain tuple—at minimum `ledger_id`, sequence, `previous_entry_sha256`, and a digest of the complete canonical semantic envelope. Never keep the predecessor pointer outside the committed entry payload: otherwise a successor can be spliced by changing only its unbound pointer. Maintain a small, strict checkpoint outside the JSONL with exact entry count and final hash; update both under the writer lock through atomic replacements and treat any ledger/anchor mismatch, missing anchor, malformed anchor, or interrupted two-file publication as unavailable. Document that a local checkpoint cannot resist a coherent deletion or rollback of both files; that requires independent immutable storage.

   **Do not overclaim this boundary.** A ledger plus anchor stored under the same writable evidence root is a corruption detector, not proof of append-only history: an actor can rewrite records, recompute the chain, and replace the colocated anchor. For shadow-evidence work, require a separately trusted anchor location or transport before describing the result as immutable or append-only. Also distinguish mismatch detection from recovery: if ledger append succeeds but anchor publication fails, do not silently repair or resume without an explicitly tested deterministic reconciliation contract.

   **Phase safely when independent anchoring is not yet approved.** Separate a pure, in-memory semantic capture/replay phase from persistence. It may validate source objects, copy their public semantics into immutable values, compute deterministic attribution, and explicitly deny persistence authority. It must not claim durable append-only history, retain mutable source-object aliases, or silently introduce a colocated-ledger substitute. For a plan-vs-signal comparison, accept the source plan through a dataclass `InitVar` (or retain only a validated immutable representation), and include each shadow line's constraint outcome, reason, and urgency in attribution so blocked and suppressed intent is not conflated with an absent shadow action.

   Before adding a durable format, add a pure replay-envelope slice that captures **only canonical builder inputs**, never derived target/plan lines or diagnostics. Replay must reconstruct typed forecasts, target, plan, typed signal snapshot, and attribution through the production builders, then require exact plan and evidence digests committed at capture. Clone every nested input record through its validating constructor; frozen dataclasses alone do not prevent `object.__setattr__` mutation of caller-owned nested objects. At the public replay boundary, reconstruct or `dataclasses.replace()` the envelope itself before consuming fields so its authority/no-persistence invariants are re-run after post-construction mutation. Add a parameterized regression that flips every declared authority field and requires replay to fail closed. Keep the envelope explicitly research-only with execution, broker, order-submission, and persistence flags denied. See `references/semantic-replay-envelope.md` for a compact field and adversarial-test checklist. Add persistence only after the path-containment mechanism and crash-recovery protocol are approved and independently reviewed. An independently administered anchor trust model is additionally required before any immutable or append-only history claim—not before a deliberately weaker local journal. A pre-anchor store must be a flat content-addressed record set (one canonical envelope per hash-named file, no mutable index/sequence/predecessor chain), return only `PENDING_ANCHOR`, and state `local-persistence-only`; recover every leaf by raw-byte hash, strict decode, and semantic replay. Any unknown, malformed, reparse-point, or ambiguous leaf makes recovery fail closed rather than returning a healthy subset.

   **Close the in-memory boundary before advancing phases.** A frozen dataclass alone does not prove derivation closure: adversarial tests should mutate nested source objects after construction and confirm the returned evidence neither retains that graph nor changes its identities. Test every semantic action/disposition that the envelope claims to classify (increase/BUY, reduce/SELL, close/CLOSE, aligned, divergent, shadow-only, suppressed, blocked, inactive). Before accepting an asynchronous review, stage every intended test and source byte, recompute the binary staged-diff digest/tree, and require the review verdict to echo that exact identity; an otherwise correct regression left unstaged is not part of the candidate.
8. **Test proof and failure modes.** Cover determinism and checksum agreement, plus incomplete/tampered receipt rejection, unsafe-root rejection, stale source rejection, factor/universe mismatch rejection, no-order authority tampering, bounded-read races, hostile scalar status values, malformed-status recovery, and ledger suffix/anchor mismatch failure closure. For a pre-anchor flat content store, run the fast false-green gate in `references/local-pending-anchor-content-store.md` immediately after the first happy-path GREEN; unknown leaves or malformed temps returning healthy status, path-based check-then-open I/O, or missing concurrency/crash tests are release `HOLD`s even when canonical replay passes.

   **Emit fresh focused evidence after the final edit.** For security-sensitive persistence repairs, make a small ad-hoc runner outside the repository (normally under the OS temporary directory) that invokes the exact new regression tests. Give pytest or similar frameworks a `tempfile.mkdtemp()` scratch root, clean the runner and scratch root afterward, and report the literal final count/result. This complements the affected suite: it proves the final bytes, avoids stale pre-edit evidence, and leaves no verification artifacts in the candidate worktree.
9. **Audit the happy-path fixture itself.** Independently parse and validate every embedded candidate, contract, evaluator/baseline identity, task/run binding, limit maximum, and review reference used by the validator's supposedly valid test receipt. If a schema-invalid candidate, arbitrary fake hashes, caller-invented control-plane facts, or an invented review hash is expected to pass, the test demonstrates a false-green validator rather than coverage. Replayed receipts must be rebound to the current invocation identity and current frozen inputs; self-hash validity alone is insufficient.
10. **Bind executed code, not a sibling file.** When a receipt claims an evaluator or validator source hash, verify the bytes of the implementation actually loaded and executed. Hashing a file in one worktree while importing the module from another checkout is a provenance cross-binding defect.
11. **Declare every content canonicalization in both contract and receipt.** If a digest intentionally treats different checkout bytes as equivalent (for example, tracked text with CRLF replaced by LF), bind an exact profile containing the hash algorithm, canonicalization transform, and scope. Include that profile in the canonical contract hash and receipt hash; require exact keys and values; and reject profile drift even when the enclosing receipt has been recomputed. Keep raw-byte hashes for generated/untracked artifacts outside the declared tracked-text scope. Every prepare, finalize, replay, and unattended producer/validator must apply the same transform.
12. **Make restart tests reuse one frozen contract.** Do not regenerate contracts independently for the pre-restart and post-restart controller, especially when issuance/expiry timestamps participate in the contract hash. Construct one contract once, persist it before the first lifecycle transition, pass it to both instances, and require every restarted transition to present the same contract hash. Regenerating `issued_at` or `expires_at` on retry is identity drift, not recovery.
13. **Test physical JSONL framing under the writer lock.** A semantically valid final row may omit its terminal newline. Before append, inspect the last byte under the same process/thread-safe lock. Either reject the noncanonical framing without changing bytes or write a separator before the next canonical row. Never concatenate two JSON objects and return success. Reparse every physical line and revalidate every receipt history after append/replay.
14. **Fault-inject every durable cut point.** Crash after contract persistence, dispatch binding, candidate write, evaluation write, decision transition, review-ready, receipt, packet, ledger append, and closure. A retry must inspect durable state and perform only missing transitions; it must not blindly restart at dispatch, duplicate events, reopen terminal state, overwrite immutable artifacts, or create a successor.
15. **Freeze every clock consumer in restart tests.** Do not monkeypatch only the runner's imported `datetime` while contract/lifecycle validators retain the wall clock. Derive `T0` at test runtime (or inject `now` explicitly), bind the same clock into every producer and validator, and probe both `T0 + epsilon` and `T0 + expiry + epsilon`. Hard-coded near-current absolute timestamps can produce a transient green suite that turns red minutes later. Contract expiry may gate new admission, but it must not prevent reconciliation or exact replay of an already admitted run.
16. **Revalidate every required companion before replay PASS.** A valid receipt plus matching persisted contract/lifecycle is insufficient when the contract names candidate, evaluation, packet, or other required artifacts. On replay, validate each required artifact's exact bytes/hash against the receipt and deterministic inputs, or reconstruct a missing artifact through an explicitly reviewed recovery rule. Replacing `candidate.json` or `evaluation.json` with independently valid JSON must never still return `PASS` merely because the receipt is self-consistent.
17. **Reset source-bound proofs after executable repairs.** Real worker, reviewer, unattended, and scheduler evidence is acceptance evidence only for its exact executable SHA. If a later adversarial review forces a source change, preserve prior receipts as historical/held and rerun the proof chain on the repaired SHA. Never rebind old evidence to new code by assertion or artifact copying.
18. **Triangulate every physical copy of a hash-bound artifact.** Independently hash the producer output, durable lifecycle copy, receipt-embedded bytes, state/event external ID, review packet, and ledger reference. Do not infer that one valid copy proves the others. A writer can hash the original bytes, persist newline-translated bytes, and later build a valid receipt from the original while the durable artifact silently differs. Generated candidates, evaluations, receipts, and ledgers remain raw-byte-bound unless their own contract explicitly declares a canonicalization scope. On Windows, production write-once helpers must use `getattr(os, "O_BINARY", 0)`, read the file back after `fsync`, and be tested with multiline bytes; a compact one-line fixture cannot expose newline translation. Any cross-copy mismatch is a release `HOLD`, even when schema validation, deterministic evaluation, receipt validation, and the focused test gate are green.
19. **Audit every public replay shortcut, not only the controller replay method.** A receipt-present or idempotent fast path must revalidate every contract-required companion—especially raw candidate and evaluation bytes—against the receipt and durable lifecycle hashes before returning `PASS`. A lower-level controller check is ineffective if the top-level runner returns from a receipt shortcut before invoking it. Add paired end-to-end regressions: complete one run; in separate scratch copies make (a) a semantically equivalent raw-byte-only candidate mutation and (b) a semantically equivalent raw-byte-only evaluation mutation, such as an appended newline, harmless whitespace, or key-order change; invoke the same public run identity; and require `HELD` with every pre-probe byte preserved. A test that changes the parsed decision or schema covers semantic tampering but does not prove raw-byte binding.
20. **Keep strict read-only SQLite audits physically read-only.** On Windows, opening a WAL-mode database with URI `mode=ro` can still create `-shm` and `-wal` sidecars beside the source. When the audit forbids any source-directory mutation, do not open the original database directly. For closed/checkpointed immutable evidence, copy the database to approved external scratch and inspect the copy. For an active database, prefer the official read-only CLI or obtain an approved consistent snapshot that includes its WAL state. Use `immutable=1` only when the database is proven frozen/checkpointed with no unapplied WAL; otherwise it can hide current rows. Inventory the source directory before and after the audit.
21. **Admission-check exactly-once reviewers before dispatch.** Generate reviewer instructions from structured current identities rather than copying the previous run's prose. Before a reviewer can become runnable, parse the generated packet and assert current source SHA; worker task/run/session; exact candidate and lifecycle paths; candidate SHA; pending receipt hash; expected focused-test count and commands; reviewer worktree source/cleanliness; and reviewer run count zero. A status label alone is not a reliable hold because board automation may promote it. Keep the reviewer profile unavailable until the pending receipt is attached and verify zero runs immediately before dispatch. Because the pending receipt binds the reviewer task ID, a one-run reviewer that returns `HOLD` for stale instructions cannot be retried or replaced against that same receipt; preserve it as held and create a fresh lifecycle.
22. **Discover forensic schemas before coding full-history queries.** Treat an audit harness as part of the proof chain. Copy frozen stores to approved scratch, run integrity checks, inspect `sqlite_master`, `PRAGMA table_info`/`table_xinfo`, indexes, and a bounded sample row, then persist a schema fingerprint before writing lifecycle/session joins. Never assume columns from an older migration or prose contract, and never instantiate a production store against original evidence because constructors may enable WAL, create sidecars, or migrate. A schema-assumption failure is an incomplete audit, not a demonstrated target defect.
23. **Budget the audit around acceptance-critical probes.** After freezing scope, execute the latest HOLD reproductions, public raw-byte replay mutations, O_BINARY/cross-copy checks, strict JSONL framing, and one schema-smoke-tested history record before broad inventories or narrative reconstruction. Make the checker restartable by phase and reserve final calls for focused gates plus opening/closing drift comparison. If a tool/session ceiling interrupts required proof, return a clearly classified audit `HOLD`; do not substitute green unit tests for unexecuted adversarial checks.
24. **Recompute lifecycle chains from exact source fields and separate harness failures from target defects.** After schema discovery, reproduce the implementation's canonical payload exactly—including `loop_id`, `sequence`, `state`, `contract_hash`, `previous_hash`, `occurred_at`, and `external_id` when those are the source-defined fields—and never substitute a prose-era field such as `event_type`. Distinguish the receipt's logical self-hash from the SHA of its physical file bytes. If a scratch checker joins the wrong table/column (for example, looking for comment text in an event row that stores only metadata), repair and rerun the checker; issue a target `HOLD` only for a reproducible implementation or evidence defect, not for a corrected audit-harness typo. For final receipt-present replay, use separate external copies for exact replay, appended candidate bytes, and a semantic evaluation mutation, and require both mutations to fail closed without repairing evidence.

25. **Drain every asynchronous acceptance gate before integration or closure.** Keep an explicit ledger of all acceptance-critical delegation IDs, exact reviewed SHA/evidence/merge scope, state, durable verdict, and replacement relationship. Resolve every running, completed-but-unread, unidentified, or metadata-only result before declaring PASS. Read the durable final summary rather than inferring a verdict from live logs. A delayed PASS cannot authorize a newer SHA; a delayed HOLD against an older SHA must be reproduced on current source or tied to a specific proven remediation before it can be dismissed.
26. **Supersede acceptance append-only when a late defect survives.** If a delayed audit exposes a defect after integration or receipt issuance, reproduce it against the accepted source, withdraw the completion claim, preserve the old receipt, and write a supersession artifact binding the old receipt hash/source/merge/finding. Reopen the board or create a linked correction card when reopening is unsupported. Add RED coverage, repair under a new SHA, and rerun every source-bound worker, reviewer, unattended, scheduler, VOT, integration, and final-audit proof before issuing replacement acceptance.
27. **Audit the complete worker session, not merely task completion.** A worker can call the Kanban completion control, produce a valid summary, and then continue taking tool actions before its agent process exits. Finalization must inspect the entire persisted session through its terminal message and reject any trailing non-allowlisted action, even if task metadata lists only the intended changed files. Before making an exact-once proof task runnable, precreate its branch at the exact source SHA and reduce the assigned profile's CLI toolsets to the minimum required surface; task-scoped Kanban lifecycle tools are injected separately. Treat `blocked` as advisory when automation can promote it. Back up profile configuration first, verify the effective parsed toolset, and restore the original bytes immediately after the run. Preserve wrong-source or over-capability attempts as explicit HOLD evidence; never trim the telemetry or retry the same supposedly exactly-once identity.
28. **Machine-synthesize receipt-bound reviewer claims after the reviewer ID exists.** A pending receipt that binds `reviewer_task_id` creates an unavoidable ordering constraint: create the non-runnable reviewer task first, finalize the pending receipt second, then generate the complete verdict block directly from the receipt object. Attach the exact block before dispatch and require the reviewer to reproduce it with a deterministic receipt-reading command and pass it unchanged to completion. Never rely on a placeholder plus manual hash transcription. One mistyped hash byte makes the executed review inadmissible even when tests, metadata, and the human-readable verdict say APPROVE; the finalizer must reject it, and operators must preserve the HOLD rather than edit the result or rerun the same identity. **Diagnose a claim-identity rejection before taking any side effect:** feed the persisted summary through the production parser, then compare every parsed field to the receipt with `repr(value)`, exact length, equality, and the first differing character/byte. Keep the receipt's logical self-hash distinct from its physical file SHA-256. A green receipt validator does not validate a manually transcribed completion block. See `references/exactly-once-reviewer-admission.md`.
29. **Close narrow exact-source audits as one transactional proof.** When only fresh focused tests/lint, delayed-expiry adversarial probes, natural one-shot scheduler provenance, and closing drift checks remain, use one unique external scratch root and an independent exact-SHA clone; do not add a worktree or open source SQLite stores. Run the compact 13-probe matrix, join the scheduler execution row to its persisted no-agent stdout artifact, wrapper, natural receipt, and current auto-removed job state, then compare complete opening/closing source/evidence/profile manifests. For an active WAL database, stably copy the matching main/`-wal`/`-shm` trio before inspection. Treat guessed Ruff filenames and stale schema assumptions as harness errors to repair and rerun, not target defects. See `references/exact-source-final-gate-and-scheduler-provenance.md`.
30. **Finalize audited acceptance append-only across the board boundary.** Write and hash the canonical acceptance receipt while board closure is still pending, obtain an independent verdict against that exact physical hash, attach the receipt and audit binding to the designated correction/acceptance card, and close the card exactly once. Do not edit the audited receipt afterward to flip a closure field. Instead, emit a separate final milestone receipt binding the immutable acceptance-receipt hash, independent audit, board closure event/task, final canonical SHA/tree, preservation readback, and retained authority denials. See `references/audit-to-kanban-finalization.md`.
31. **Audit post-integration acceptance as a claim-to-proof transaction.** Hash the final acceptance receipt first, then map every material field to exact Git facts, physical artifacts, copied-database rows, live read-only control observations, or fresh exact-merge gates. Prefer two restartable external-scratch checkers (static preservation and evidence lifecycle) over a long one-off command chain, and reserve calls for the mandatory closing drift pass. For expiry behavior, inject `expires_at + epsilon`; do not use wall time, because a not-yet-expired contract can create a false audit HOLD. Classify and rerun harness mistakes without blaming the target. See `references/post-integration-acceptance-audit.md`.
32. **Adjudicate auditors that hit the execution ceiling fail-closed.** A wrapper-level `max_iterations` warning does not erase an explicit verdict already emitted, but `status=completed` never proves PASS. Accept the result only when the append-only transcript contains an unambiguous terminal verdict and a machine-readable external-scratch report independently records the same verdict, exact identities, complete required check inventory, zero failures, and closing no-drift evidence; hash all of those artifacts. Otherwise classify it as `HOLD_AUDIT_INCOMPLETE` and dispatch a narrow replacement. See `references/async-audit-drain-and-acceptance-supersession.md`.
33. **Freeze the executed source identity before supervised evidence.** `git rev-parse HEAD` is not a sufficient source claim when dirty tracked files or untracked executable modules can be imported. A cleanliness probe that uses `--untracked-files=no` is specifically unsafe for this purpose. Before issuing a supervised receipt, either commit the complete executable slice locally and prove every loaded module is tracked and byte-identical to that commit, or bind a canonical dirty-worktree manifest covering HEAD, tracked diff bytes, every untracked executable/config file, imported module paths and raw hashes, and dependency versions. Include untracked files in the preflight, inspect actual `module.__file__` paths, and reject evidence generation when the claimed revision does not identify the bytes that ran. See `references/frozen-research-panel-and-source-identity.md`.
34. **Bind asynchronous pre-commit reviews to the exact staged diff.** Before dispatch, record HEAD, `git diff --cached --binary --no-ext-diff` SHA-256, the sorted staged path list/count, and whether any staged path also has unstaged bytes. Include those identities in the reviewer packet. Immediately before accepting the verdict or committing, recompute them. Any newly staged file, formatting change, wrapper replacement, dependency-lock correction, or other diff drift makes the old verdict stale even when it says PASS; preserve it as review history and dispatch a replacement against the new digest. Never infer that a reviewer which read the repository late necessarily covered the final staged bytes—require its final verdict to echo the bound digest and path count.
35. **Close versioned protocols recursively, not only at the root.** For every nested object, require the exact key set for that schema version and strict scalar types before semantic comparisons. In Python, `bool` is an `int` subclass, so use `type(value) is int` for counts, limits, seeds, and timeouts; reject booleans, floats, strings, unknown nested fields, and omitted authority denials. Adversarially mutate one nested section at a time—data, evaluator, runtime, model config, authority—and require validation to fail even after the enclosing JSON/hash is recomputed. Root-level unknown-key tests do not prove nested closure.
36. **Build identity graphs leaves-first and include transitive implementation dependencies.** Enumerate the evidence DAG before pinning hashes. Authority extracts, prospective-selection manifests, source replay reports, and immutable source files are leaves; bind their raw hashes into the protocol; then derive dataset, feature, evaluator, release, staged-diff, and independent-review identities in that order. A feature-builder hash must cover every helper that changes admission, pivots, normalization, calendar/label construction, or output bytes—not only the public top-level function. If any later edit adds a field or evidence binding after a parent hash was computed, that parent and every descendant are stale: preserve old artifacts as historical/held and regenerate to new content-addressed paths. Add mutation probes for helper source, bound evidence bytes, alternate protocol paths, and zero-cost/relaxed-threshold protocols before accepting the identity chain.
37. **Separate calendar authority from archival transport.** When a current exchange page covers only future years, recover historical bytes from archived pages whose original host is the exchange or its owner; record both the official origin URL and the archive URL/timestamp, and hash the captured raw bytes. Use annual official closure tables for regular dates and separate official exchange press notices for exceptional closures. If an old page is a dynamic shell, inspect its named partial/data endpoints or a later capture rather than filling dates from a generic holiday formula. A market-data gap, federal proclamation, or third-party calendar can corroborate but cannot alone establish the exchange schedule. Persist the complete supported closure map, exact source-to-year coverage, observance footnotes, exceptional-closure claims, and an explicit statement that the archive is transport rather than authority. Regression-test generated sessions against every published full-day closure, keep early closes as sessions, and bump the calendar/evidence version whenever one date changes. See `references/authoritative-calendar-evidence.md`.
38. **Separate semantic builders, serializers, and actual runtime identity.** A semantic feature/data hash does not identify the code that canonicalizes manifests or writes Parquet/JSON. Bind transitive semantic helpers, a distinct materializer/serializer source hash, and actual Python/library versions that can affect source reads, calculations, or physical bytes. A requirements lock alone is not execution evidence. Dataset manifests should bind source/evidence hashes, builder/materializer, runtime, recipe, calendar, and output; feature manifests should additionally bind the exact dataset-manifest hash and both feature identities.
39. **Prove regeneration with a recoverable two-pass raw-byte replay.** Idempotently reopening an existing manifest is not regeneration proof. Copy a durable pass-1 artifact set to a private replay root, verify every copy, remove only the canonical outputs, rebuild pass 2 from frozen inputs, and compare raw hashes, raw bytes, canonical manifests, and identity fields. Restore pass-1 bytes on any build or comparison failure. Do not edit source while an `inspect.getsource`-based materializer identity is running.
40. **Run physical evidence-tamper probes in a copied root.** Copy the protocol and all relative evidence leaves, redirect canonical-root constants in the test process, prove untampered load, mutate one copied byte, require the exact rejection reason, then restore and prove the original identity. Never risk canonical evidence for a rejection test. When a numerical probe fails, read the strict production predicate before changing code; a fixture that never crossed the threshold is a harness defect, not a target defect.
41. **Avoid circular release identities.** A wrapper containing the expected release-manifest hash cannot also be raw-hash-bound inside that same manifest. Exclude it and bind it in an outer staged/release anchor, or redesign around a non-self-referential anchor. Release verification should still enforce canonical manifest bytes, exact identities, contained worktree paths, approved artifact roots, and physical artifact hashes. See `references/versioned-artifact-identity-and-exact-replay.md`.
42. **Separate pytest temp isolation from application-write isolation.** `TMPDIR`/`TEMP`/`TMP` plus `--basetemp` isolate pytest fixtures and cache, but they do not stop tests or subprocesses from writing hard-coded `ROOT/artifacts`, local databases, generated assets, or other repository-relative paths. For a broad suite containing fixed-root writers, build a disposable Git-aware snapshot of the exact dirty candidate outside the worktree and run the suite there. Start from exact `HEAD`, apply the tracked diff, copy untracked candidate files, preserve deletions, then overwrite every candidate path from the source worktree byte-for-byte: on Windows, checkout/apply filters can make a semantically identical patch raw-byte different through CRLF/LF conversion. Hash-compare every candidate path before execution, inventory it again afterward, and independently compare opening/closing canonical evidence and Git-state fingerprints in the source worktree. Treat an in-worktree run that wrote fixed-root outputs as diagnostic but non-admissible for an isolation claim; rerun externally rather than deleting unknown ignored files. Compare broad failures node-for-node against the historical baseline and classify missing local prerequisites separately from new relevant failures. See `references/dirty-candidate-disposable-test-snapshot.md`.
43. **Test supersession references as path-and-content bindings.** A supersession object binds both the predecessor path and its canonical/raw hash. In regression tests, resolve the predecessor from `receipt["supersedes_receipt"]["path"]` under an approved contained root, then hash those exact bytes and compare them with the adjacent declared hash. Do not hash a detached hard-coded predecessor constant while reading only the hash from the receipt: a path-only mutation would remain green. Also assert the expected predecessor path when the protocol fixes it, and add a path-only mutation probe that must fail even when the declared digest is unchanged. Apply the same rule to universe, contract, packet, candidate, evaluation, and other `{path, hash}` evidence pairs.
44. **Capture exact-once API returns before uncertain post-processing.** When a selection, holdout, reviewer, scheduler, or other acceptance-critical API may be called only once, pre-validate the downstream methodology and then persist the returned structured value immediately to unique external scratch before calculating aggregates or asserting them. Hash that scratch capture and delete it after the complete closing pass. If aggregation fails, repair the harness against the captured return; never spend a second one-shot call on a bootstrap, date, formatting, or checker mistake. Without a capture, classify the API-bound aggregate proof as incomplete rather than silently substituting an independent reconstruction.
45. **Treat time and checkout representations as explicit evidence semantics.** For exchange session-date claims, compare the declared date projection rather than assuming stored timestamps are UTC midnight; local midnight may appear as `04:00:00` UTC. For historical source hashes on Windows, distinguish Git blob LF bytes from executed checkout CRLF bytes by inspecting attributes and checkout policy. Resolve these representation questions before classifying a mismatch as a target defect, and never silently canonicalize when the contract claims raw bytes.
46. **Reject behaviorally correct but cryptographically unreproducible parity receipts.** Exact forecast/ranking/signal parity does not validate a receipt whose dataset digest lacks its complete serialization contract or whose run-manifest digest lacks a recoverable preimage. The receipt must bind source/window/as-of rules, universe and row/column ordering, scalar/date/float representation, framing/canonicalization, and hash algorithm; a manifest must be embedded or named by an exact contained path plus raw hash. Perform the expensive model computation once, capture structured outputs, and diagnose hash-profile candidates without repeating the model invocation. If parity reproduces but a material digest cannot, return `HOLD_EVIDENCE_UNREPRODUCIBLE`: do not allege dishonesty without proof, and do not accept the exact receipt. See `references/shadow-ranking-parity-receipt-audit.md`.
47. **Audit the exact staged representation and define one-shot at the public computation boundary.** For staged receipt reviews, extract or stream the index blob itself before parsing or hashing; do not silently substitute checkout bytes, because Windows text conversion can make a clean worktree raw-byte-different from the staged candidate. Record both representations when they differ, but bind the verdict to the declared staged blob. Treat “one-shot model computation” as one invocation of the audited scoring workflow, not necessarily one low-level `predict()` call: implementations may legitimately call the predictor once per symbol or batch. Persist the complete score map immediately after that workflow returns, before asserting call counts, ranking, formatting, or provenance. If a later harness assertion is wrong, repair downstream checks against the captured scores and prove no further predictor calls occurred; never rerun the expensive workflow merely to satisfy an auditor-invented internal call-count assumption. See `references/shadow-ranking-parity-receipt-audit.md`.

## Review checklist

- No provider, broker, order, scheduler, database, or secret path is introduced unless explicitly authorized.
- Canonical JSON and hashes are stable under equivalent input ordering.
- The persisted receipt can be recomputed from its embedded frozen inputs.
- A reader never accepts a primary artifact without its matching integrity companion.
- Artifact paths are contained beneath the approved root at every filesystem boundary.

## Pitfalls

- A `PASS` status plus a digest is not proof if the writer cannot recompute the payload.
- Writing JSON and checksum with two independent file replacements exposes a partial-publish window; use a generation directory/commit protocol.
- A function accepting arbitrary `output_path` is a file-write authority boundary, even when intended for local-only evidence.
