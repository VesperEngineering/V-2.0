# Immutable Operator-Terminal Commit Review

Use this checklist for a read-only review of a fixed local commit, especially after a rebase.

## Freeze and drift detection

1. Before reading the diff or running tests, capture and assert the expected:
   - `git rev-parse HEAD`
   - `git rev-parse HEAD^`
   - `git rev-parse 'HEAD^{tree}'`
   - empty `git status --porcelain=v1 --untracked-files=all`
2. Review exactly `git diff HEAD^ HEAD`; do not silently widen to another branch or obsolete commit.
3. Reserve a final tool call for the same four assertions. Run it before optional polish if the tool-call budget is getting low. Any mismatch is a review failure, even if tests passed.
4. Direct generated bytecode and pytest scratch outside the repo (`PYTHONPYCACHEPREFIX`, external `--basetemp`, `-p no:cacheprovider`) so read-only verification does not create review noise. On Windows under Git Bash/MSYS, pass a **native Windows path** to Windows Python: create scratch with `mktemp`, convert it with `cygpath -m`, and use the converted `C:/...` value for both variables. A raw `/c/...` `--basetemp` can be interpreted as a repo-drive-relative path and turn an otherwise healthy suite into fixture setup errors.

## Governance and canonical-parent check

- Read root governance files before interpreting authority-bearing code. Environment variables, CLI actor names, and config labels are not authenticated identities.
- Compare changed paths with the canonical parent patch. No overlap lowers mechanical reversion risk, but semantic reversions still matter: inspect changed assertions for safety invariants flipped from false to true.
- Keep findings from source behavior separate from environment-only launcher or asset failures.
- Scan the commit for credentials and new mutation capability without echoing suspicious source text. A safe scanner should emit only category, path, line number, and counts; never print a matched credential value into logs, prompts, or chat. Pair pattern scans with structural checks such as handlerlessness and an always-rejecting execution boundary—keyword absence alone is not proof that submission is unavailable.

## Adversarial probes that unit tests commonly miss

### Visibility before mutation

Changing controller state to `overlay=...` is not proof the operator saw it. Attach an application spy whose `invalidate()` increments a counter. The first embedded action must:

- open the correct overlay;
- select the exact row;
- perform zero mutation; and
- explicitly invalidate/redraw before a second key can mutate.

Probe direct public controller methods as well as keyboard dispatch. Approval and issue paths should have symmetric redraw behavior.

### Approval-ledger authority

- A hash over request fields does not protect later decision or authority fields. Flip `approval_granted` or `execution_authorized` in a temporary event while leaving the request hash unchanged; replay must reject it or force the hard-closed value.
- Also forge a complete-looking decision in one request event by changing `status`, event type, decision actor, decision time, and decision reason while keeping the request hash and hard-false authority flags unchanged. Replay must reject it; hard-false execution alone does not make a forged `APPROVED` attestation truthful.
- Test deletion at every chain position: first, middle, final, and the whole log, plus reordering. A linked hash chain detects edits or removals only when a surviving successor still references the missing hash; it does **not** detect suffix truncation or whole-log deletion by itself. If the contract says every deletion must fail replay, require and verify a separately durable trusted tail anchor, event count/checkpoint, or authenticated signature rather than claiming an ordinary chain is append-only.
- Until principals are cryptographically or OS-session authenticated, decisions are attestations: do not derive authority from `.env`, process environment, CLI strings, or display names.
- Verify normal approval, tampered replay, expiry, repeated decisions, self-approval, and zero execution receipts when execution is closed.

### Provider last-good behavior

Test malformed JSON, top-level null, null `data`, mapping instead of list, non-mapping rows, booleans, fractional counts, NaN/infinity, negative values, and integers too large for `float()`. Numeric conversion can raise `OverflowError`; it must be classified as malformed provider data and retain the exact last-good stale cache rather than escape the source boundary.

### Rendering and bounded review

- Exercise the exact supported size matrix, not just one large fixture.
- Assert line count and **terminal-cell width**, not only Python `len()`, at every size. Use `wcwidth.wcswidth` or the terminal toolkit's cell-width helper; CJK/emoji can be two columns even when one code point.
- For multi-row queues, select an item outside the first window and prove it remains visible.
- Test the approval overlay at the dimensions actually produced by the smallest supported terminal (viewport minus float margins), with the maximum allowed action, scope, **and reason present simultaneously**. Use distinct sentinel characters absent from labels; assert exact counts for every field and require the authority warning plus action footer to remain visible. A per-field maximum is unsafe if the combined request can still be clipped.
- Make pre-write fit validation call the same canonical wrapping/measurement path as rendering. Prefixes alter tab stops: a raw value may fit at 68 columns while `LABEL + value` needs another row. Reject tabs and other control whitespace or canonicalize them **before** hashing. When the contract requires rejection, inspect the raw value before any `.strip()`/`.trim()` call: trimming first silently erases leading/trailing tabs, CR/LF, and similar controls and can turn forbidden input into a durable event. Probe controls at the beginning, middle, and end (including `\t`, `\r`, `\n`, C0/C1 controls, and Unicode category `C`), plus spaces, long words, and wide Unicode. For every rejected request, assert that neither the event ledger nor its durable head/count checkpoint or temporary file was created.
- Audit every operator-visible authority claim, not just the embedded card or controller message. Review overlays, key footers, command help, docs, and success/status messages must describe decisions as attestations and `E`/`execute-approval` as a closed gate check when execution is structurally unavailable. A help entry saying “grant” or “run” is a correctness failure even if the implementation always raises.

## Pure fail-closed view-model contract review

When a frozen terminal candidate adds a pure view model or state resolver, do not stop at the happy-path unit suite. Probe the model boundary directly with hostile but side-effect-free values:

1. **Completion state must consume verification.** If the UI contract says `COMPLETE` requires an artifact/receipt and passing verification, the state resolver itself must enforce that requirement. A separate `has_verified_receipt()` helper does not prevent the primary card state from going false-green. Also check aggregate selectors: filtering raw `done`/`archived` rows before schema/error resolution can hide malformed or unverified roots entirely.
2. **Contradictions must not be laundered by precedence.** Exercise combinations such as `done + needs_review`, `blocked + needs_review`, `running + stale heartbeat`, and closed status plus schema error. Compare the implemented precedence with every broad invariant in current docs, not only with a narrow pseudocode example.
3. **Numeric timestamp conversion must be total.** Test timezone-aware datetimes, naive datetimes, epoch seconds, milliseconds, numeric strings, booleans, NaN/infinity, negative/future values, and a huge integer such as `10**10000`. Put `float(value)` inside the guarded conversion block; otherwise `OverflowError` can escape before `datetime.fromtimestamp()` is reached.
4. **Objective selection must expose unsafe roots.** Test multiple evidenced roots, waiting-only roots, duplicate IDs, orphaned parents, closed parents with active children, schema-invalid closed roots, and unverified completion. A fail-closed selector may decline to choose, but it must not silently erase contradictory evidence from the operator inventory.
5. **Frozen dataclasses are only shallowly immutable.** Attempt external mutation of every nested field. Types such as `tuple[object, ...]` can contain mutable lists/dicts, change after construction, and become unhashable. Require recursively immutable scalar/tuple/frozenset structures or canonicalized signatures.
6. **Authority-bearing models must encode bindings, not booleans alone.** A pending-ID set cannot prove request ID, exact task/action/scope, expiry, principal separation, and source validity. Construct an authority card with both authorization flags true; if the current contract is structurally closed, the model should reject or derive those values from a validated source rather than trust caller-supplied booleans.
7. **Separate current reachability from unsafe future seams.** Search all production callers and side-effect primitives. If the new module has no runtime caller and no I/O/process/database/network primitive, report that no immediate authority path was added while still blocking an unsafe foundational contract that future adapters would consume.

Run these as inline Python probes with bytecode disabled or as external-temp tests, then recheck the frozen Git state. Passing focused tests never overrides a demonstrated hostile-value failure.

## Master engineering documentation candidates

A new architecture or “master engineering” document needs a truth/authority pass in addition to link checking:

- Classify each diagram and table as **current**, **candidate**, or **target**. An unconditional arrow from approval to an action handler is a false capability claim when the current handler always rejects or does not exist.
- Cross-check labels such as “authenticated,” “append-only,” “active,” and “verified” against implementation. An append operation is not tamper evidence; a display principal or environment value is not authenticated identity.
- Check the document against its own verification matrix. If it requires source-state, malformed-input, authority, or immutability tests, verify those tests actually exist and exercise behavior rather than enum construction.
- Prevent subordinate documentation from self-promoting into governance. A file marked descriptive and ranked below `AGENTS.md`/coding standards cannot by itself declare that every future engineering slice “must” update it or is incomplete without it. Put mandatory process rules in an authoritative governance surface, or word them as recommendations.
- Validate every repository-relative linked path against the candidate commit, not merely against machine-local untracked files. Report local-but-untracked plans as non-reproducible references.
- Run repository documentation freshness checks when policy requires them, but classify failures against the exact diff inputs. If all validator inputs are unchanged, report the failure as pre-existing rather than candidate-introduced.

## Reporting

Return a concise PASS/FAIL with blocking findings first, then verified passes, non-blocking suggestions, and environment-only failures. Every blocker should include candidate `file:line`, mechanism, consequence, the smallest precise fix, and an observed probe when one is decisive. Passing focused tests never overrides a demonstrated fail-closed or authority invariant violation.
