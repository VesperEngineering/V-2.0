# Vesper Factor Integration Skill

## Description
This skill contains historical implementation detail for Vesper's factor pipeline, dashboard, Alpaca paper integration, insider signals, and research loop.

## Authority and Overlap

This skill overlaps the newer class-level `vesper-factor-workflow` umbrella. For current registry, scheduling, artifact admission, factor governance, and broker-order safety, **load `vesper-factor-workflow` first and treat it as authoritative**. In particular, follow its `references/fail-closed-morning-artifacts-and-paper-orders.md` reference.

The schedules, factor counts, weights, database row counts, dashboard details, and code snippets below are historical snapshots unless independently verified against the current worktree and `docs/STATUS.md`. Do not execute broker or scheduler instructions from this historical section merely because they appear here.

The user acts as an **orchestrator** — the system should run autonomously only after current data and execution gates pass; they intervene when changing strategy or authority.

The dashboard (`scripts/factor_dashboard.py`) is the primary monitoring interface. It uses a **Monitor View layout** at 1920×1080:
- **Top**: Cron Schedule — 8 jobs with individual HH:MM:SS countdowns and progress bars
- **Left**: Factor Scores table (10 columns: Ticker, Trend, Score, Entropy, Hurst, Vol, Sent, Insider, Massive, Top) + Bar chart
- **Right**: Alpaca Portfolio panel with P&L + Today's Data live feed
- **Bottom strip**: Vesper Selection, Factor Basket, Log — three panels side by side
- **Status bar**: Market hours indicator + alert thresholds

Design principles (from research):
- **Maximum information density** (Bloomberg/Tufte): Unicode sparklines ▁▂▃▄▅▆▇, color-encoded scores, compact layout
- **5-6 colors max**: green (#4ec9b0) for positive, red (#f44747) for negative, white (#d4d4d4) for neutral
- **Dark theme**: BG #1e1e1e, FG #d4d4d4, selection #264f78, clam theme

**Editing compact or heavily modified files**: fuzzy/context patches can unexpectedly remove or re-indent adjacent lines. Use a unique, narrowly scoped match; after every edit, re-read the exact region, inspect the diff, and run the cheapest syntax/import check before another patch. Never stack behavioral edits on a syntactically broken file. Do not rewrite a large file unless you have verified there are no external edits.

**Subprocess isolation and fail-closed scoring**: `run_all_factors.py` may isolate factors with per-factor timeouts, but the morning pipeline must not silently publish or reuse artifacts when a core live factor fails. Generated `python -c` payloads require their own compile-level regression test because the parent runner can be syntactically valid while emitting invalid child Python. Surface child stderr, require non-empty scores from the declared core factor set, return a nonzero process exit on admission failure, and stop basket generation. Optional/informational factor failures may be recorded explicitly, but never silently change the core strategy denominator.

**Score file format**: `data/factor_scores_YYYYMMDD.json` with keys `scored` (all ranked tickers), `scored_count`, `top_10`, `factor_features` (list of factor names used).

### 3. Integration into No-Order Report
**File:** `deploy/src/na/paper_no_order_report.py`
After `_build_candidate_selection()`, insert factor scoring re-rank:
```python
try:
    from datetime import timedelta
    from app.services.vesper_factor_integration import apply_factor_scores_to_basket
    score_date = (run_day - timedelta(days=1)).strftime('%Y%m%d')
    candidate_tickers = [c.ticker for c in selections]
    factored_tickers = apply_factor_scores_to_basket(
        candidates=candidate_tickers,
        date_str=score_date,
        top_k=len(candidate_tickers),
        use_factor_only=True,
        factor_weight=1.0
    )
    ticker_to_candidate = {c.ticker: c for c in selections}
    new_selections = []
    for t in factored_tickers:
        if t in ticker_to_candidate:
            new_selections.append(ticker_to_candidate[t])
    if len(new_selections) < len(selections):
        remaining = [c for c in selections if c.ticker not in [t for t in factored_tickers if t in ticker_to_candidate]]
        new_selections.extend(remaining)
    selections = tuple(new_selections)
except Exception:
    pass
```

### 4. Alpaca Paper Trading + Portfolio Snapshot
**Files:** `scripts/alpaca_rebalance.py`, `scripts/alpaca_portfolio.py`

- Rebalance script reads latest factor basket, sells mismatched positions, buys target with equal weight
- **Critical**: Never globally cancel every open Alpaca order. Reconcile and cancel only orders positively owned by the rebalance strategy (client-order-id/tag), because unrelated protective stops may exist. Serialize rebalance and protective-order writers before enabling either unattended.
- Portfolio snapshot writes `artifacts/evals/alpaca_portfolio_YYYYMMDD.json` with equity, cash, per-position P&L
- Dashboard displays: Equity, Cash, positions count, BP, and total unrealized P&L
- Cron for snapshot: `0 20 * * 1-5` (Mon-Fri, 4pm ET close)

### 5. Insider Trading Signal
**File:** `scripts/insider_trades.py`
- Fetches insider trades from Financial Modeling Prep API (if `FMP_API_KEY` in `.env`)
- Falls back to local cache if API unavailable
- Computes `insider_score = (buys - sells) / (buys + sells + 1)` per ticker (range -1 to +1)
- Stores scores to `data/insider_trades/insider_scores.json`
- Integrated into `daily_factor_scores.py` as the `insider` feature

### Pipeline Guards — Current Authority

The dated guard list previously stored here is superseded. Use `vesper-factor-workflow` and its fail-closed morning-artifact reference. The current class-level requirements are:

1. Resolve the prior XNYS session and require the active source database to end on that exact date before scoring.
2. Carry the source session through score JSON, basket filename, heading, and embedded provenance; reject touched/relabelled old files.
3. Derive the age limit from the actual configured producer/consumer gap plus runtime and jitter; never copy an old fixed minute value.
4. Require explicit factor weights, finite/non-empty successful scores, and all declared core factors.
5. Run scores → basket → dashboard as one timeout-bounded, singleton, first-failure chain.
6. Treat paper execution as a broker lifecycle: validate assets, abort on unowned/unknown open orders, fill reductions before buys, refresh positions, verify terminal buy fills, and return nonzero on unknown state.
7. Do not call a four-sector basket benchmark-neutral unless benchmark exposures are actually neutralized.

## Troubleshooting

- **Alpaca orders fail with "notional must be 2 decimal places"**: Round all notional values with `round(val, 2)` before sending
- **Stale or duplicate Alpaca orders**: Query open orders, reconcile by strategy-owned client-order IDs, and cancel only the rebalance strategy's stale orders. Never use a global cancel when protective stops or another order writer may be active.
- **Missing cron scripts**: Cron shell scripts live in `C:\\Users\\bgonn\\AppData\\Local\\hermes\\scripts\\` — check they exist if jobs show `last_status: error`
- **Factor score file missing `scored` key**: Old files only have `top_10` — dashboard falls back gracefully
- **Macro duplicate index errors**: Dedup `expanded_index` before reindex in `macro_loader.py`
- **`python` resolves to wrong venv (3.10)**: The terminal picks up `veyr-music/heartlib/.venv`. Use full path: `/c/Users/bgonn/AppData/Local/hermes/hermes-agent/venv/Scripts/python.exe` for pytest and cron scripts
- **pytrends returns 429 (rate-limited)**: Cannot fix in code — Google blocks after ~20 requests. The Wikipedia factor is the primary retail attention signal. Google Trends factor has a 15s subprocess timeout to prevent pipeline hangs
- **`from datetime import UTC` fails**: Python 3.10 doesn't have `UTC`. Use `from datetime import timezone` and `timezone.utc` for 3.10+ compat
- **Pre-commit hooks reformat entire dashboard**: The compact dashboard uses semicolons for density. Pre-commit ruff-format expands it to 800+ lines. Commit with `--no-verify` for GUI-only changes, or accept the reformatting
- **`run_all_factors.py` stalls or a factor times out**: Keep per-factor subprocess timeouts, but apply admission policy after collection. An optional informational factor may be recorded as unavailable; any declared core factor that times out, errors, or returns empty/nonfinite scores must make the whole score publication return nonzero.
- **A broad patch is rejected or affects adjacent code**: Split it into one exact, file-scoped replacement at a time. Re-read the edited region after each change, inspect the diff, and run the cheapest syntax/test check before stacking another behavioral edit. Atomic multi-file patches may reject every hunk when only one anchor is ambiguous.
