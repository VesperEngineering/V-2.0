# Split Adjustment Implementation

Concrete implementation pattern for forward-adjusting OHLCV prices to remove
stock-split discontinuities. Built and verified 2026-07-14.

## Problem

`sp500_ohlcv.sqlite` stores raw unadjusted prices. NVDA's 10:1 split (June 10,
2024) drops from $1,208.88 to $121.79 — a ~90% non-economic "return" that every
factor interprets as real. 240 splits detected across 174/502 tickers.

## Solution: `app/factors/db.py`

Two functions added:

1. **`fetch_adjusted_ohlcv_rows(conn, date_list, ...)`** — drop-in replacement for
   `fetch_ohlcv_rows`. Returns `list[dict]` instead of `list[sqlite3.Row]` but
   `r['close']` / `r['ticker']` access works identically. Applies cumulative
   forward-adjustment factors to close/open/high/low columns.

2. **`get_split_adjustment(ticker, date, root=".")`** — returns the adjustment
   factor for a single (ticker, date) pair. Returns 1.0 for unknown tickers.
   For raw-SQL consumers that can't use the row fetcher.

## Adjustment file: `vesper_data/split_adjustments.json`

JSON dict: `{ticker: {date: cumulative_factor}}`. Generated by `scripts/detect_splits.py`.
- 240 splits across 174 tickers
- Factor = cumulative forward-adjustment: adjusted_price = raw_price × factor
- Post-split dates have factor 1.0; pre-split dates have factor < 1.0
- Regenerable from primary DB at any time

## Detection methodology

```python
# Iterate BACKWARD through each ticker's price history
cum_factor = 1.0
for j in range(len(rows) - 1, -1, -1):
    adjustments[rows[j]['date']] = cum_factor
    if j > 0:
        forward_ratio = rows[j]['close'] / rows[j-1]['close']
        n = is_likely_split(forward_ratio)  # check against standard ratios ±2%
        if n is not None:
            cum_factor *= (1.0 / n)
```

Standard split ratios checked: 2:1, 3:1, 4:1, 5:1, 7:1, 10:1, 20:1 (±2% tolerance).
Real crashes (AIG 2008) don't match clean ratios and are correctly excluded.

## Factor migration checklist

For each factor reading from `sp500_ohlcv.sqlite`:

1. Change import: `fetch_ohlcv_rows` → `fetch_adjusted_ohlcv_rows`
2. Change call: `fetch_ohlcv_rows(...)` → `fetch_adjusted_ohlcv_rows(...)`
3. No logic changes needed — return type change is transparent
4. Verify: run factor and confirm split-crossing tickers score mid-rank (not extremes)

## Raw-SQL consumers (special case)

Factors that use raw SQL queries (not `fetch_ohlcv_rows`) need manual adjustment:

1. Add import: `from app.factors.db import get_split_adjustment`
2. Fetch dates alongside prices: `SELECT date, close FROM sp500_ohlcv WHERE ...`
3. Apply: `closes = [r[1] * get_split_adjustment(ticker, r[0], root=root) for r in rows]`

See `sp500_technical.py` for the worked example.
