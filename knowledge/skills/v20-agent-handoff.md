# V20 agent handoff

## When to use

Use when transferring an unfinished or review-ready task between V20 specialists or operator sessions.

## Procedure

1. Name the objective, current native-platform run/task identity, repository revision, workspace, and owner.
2. Separate verified results from assumptions. Cite exact files, receipts, checks, and failures.
3. State completed work, remaining work, allowed paths/tools, denied authority, and the next executable step.
4. Preserve unrelated worktree changes and identify any concurrent owner or collision risk.
5. Bind review-ready claims to the exact candidate diff or revision and actual verification output.
6. Stop at a genuine approval, credential, external-state, or authority boundary; never represent a handoff as acceptance.

Keep the handoff self-contained and concise. Native controller state and repository evidence outrank chat summaries.
